## 1. Что это за проект

**«Кухонный помощник»** — приложение, которое решает вопрос «что приготовить?».

Пользователь проходит короткую анкету (тип питания/кухня, цель по КБЖУ, что использовать, что исключить, время,
количество порций, техника), после чего приложение:

1. ищет подходящие рецепты в интернете;
2. отдаёт находки языковой модели, которая собирает **один готовый рецепт**;
3. показывает точные количества, калорийность и **КБЖУ на одну порцию**, пошаговую инструкцию;
4. формирует список продуктов со ссылками на поиск в магазинах (Пятёрочка, ВкусВилл, Перекрёсток, Лавка, Купер).

Дополнительные режимы:

- **Меню на день** — несколько приёмов пищи генерируются одним запросом, чтобы продукты переиспользовались;
- **План питания на 3 дня** — сначала корзина продуктов на весь период, затем рецепты по дням из реального остатка;
- **Книга рецептов** — общая библиотека всех сгенерированных рецептов с фильтрами и поиском;
- **Дневник питания** — запись съеденного, итоги дня, графики калорий и веса;
- **Избранное**, списки покупок, PDF-экспорт, подписка и оплата, партнёрская и реферальная программы.

Ключевая особенность: **одно ядро — два интерфейса**. Telegram-бот и сайт (PWA) используют общие модули
поиска, генерации, парсинга и хранения, но запускаются как два независимых процесса.

| Параметр | Значение |
|---|---|
| Язык | Python 3.11 / 3.12 |
| Telegram-бот | aiogram 3.13 (long polling) |
| Сайт / API | FastAPI 0.115 + uvicorn, фронтенд — один HTML-файл без сборки |
| Планировщик | APScheduler 3.10 (напоминания, дайджесты, автопосты) |
| Хранение | SQLite (`accounts.db`, `usage.db`, `web_data/web.db`) + JSON-файлы |
| PDF / картинки | reportlab, Pillow |
| Внешние сервисы | DeepSeek / Groq / OpenRouter (LLM), Tavily / DuckDuckGo (поиск), ВкусВилл MCP, PayAnyWay, Telegram Stars, ВК |
| Тесты | 56 скриптов в `tests/` (запуск через `tests/run_all.sh`) |

## 3. Точки входа и запуск

| Что | Файл | Команда |
|---|---|---|
| Telegram-бот | `bot.py` | `python bot.py` |
| Сайт + API + админка | `web_api.py` | `uvicorn web_api:app --host 127.0.0.1 --port 8081` |

В `bot.py` функция `main()`:

- проверяет наличие `BOT_TOKEN`;
- настраивает планировщик (`setup_scheduler`) — напоминания, дайджесты, автопосты, тревоги;
- чистит устаревшие сессии и старые анкеты;
- восстанавливает таймеры готовки и «зависшие» генерации;
- регистрирует команды и запускает `dp.start_polling(bot)`.

Роутеры бота подключаются в конце `bot.py` в порядке:
`bot_profile → bot_cook → bot_shop → bot_extras → bot_vision → bot_social → bot_diary → bot_promo → bot_book → digest → fallback`.

В `web_api.py` создаётся `FastAPI(title="Kitchen")`, монтируются статика (`/uploads`, `/icons`) и определяются
маршруты: страница `/`, API `/api/*`, админка `/admin`, PDF `/api/pdf`, PWA-файлы, SEO-страницы
(`/pitanie`, `/recepty`, `/r/...`, `/rc/...`, `/l/...`), оплата `/pay/...`.

> Порты: в docstring `web_api.py` указан пример `:8081`; по `PROJECT.md` на сервере веб-процесс `cooking-web`
> слушает `:8101` за nginx (`https://menu.ymayaka.ru`), бот работает отдельной systemd-службой `Cooking`.

## 4. Ключевые модули

### 4.1. Ядро генерации (общее для бота и сайта)

| Модуль | Ответственность |
|---|---|
| `search.py` | веб-поиск рецептов: Tavily → DuckDuckGo → DeepSeek Search; строит запрос из анкеты |
| `ai.py` | обёртка над LLM; фолбэк DeepSeek → Groq → OpenRouter, `generate_recipe`, `call_llm_with_fallback` |
| `prompts.py` | все промпты и контракт служебных строк (`ПРОДУКТЫ_СПИСОК`, `БАЗОВЫЕ_ПРОДУКТЫ`, `ИСПОЛЬЗОВАНО_БАЗОВЫЕ`, `ПРИЁМ_ПИЩИ`) |
| `cuisines.py` | единый справочник типов питания и правил для промптов |
| `profile_ctx.py` | передача списка «исключить» в промпт и проверка ответа модели |
| `shopping.py` | вырезание и разбор служебных строк, ссылки на магазины |
| `recipe_math.py` | пересчёт порций и объединение продуктов без участия ИИ |
| `missing.py` | замена отсутствующих продуктов / переделка блюда, меню или плана |
| `book.py` | книга рецептов: поиск готового рецепта до вызова ИИ, пополнение библиотеки |
| `tailor.py` | адаптация рецепта из книги под конкретного человека (премиум-функция) |

Принцип: **арифметику (остатки, лимиты, упаковки) считает код, а не модель**.

### 4.2. Режимы

| Модуль | Ответственность |
|---|---|
| `day_menu.py` | «Меню на день»: совместная генерация нескольких блюд, разбор блоков, хранение в `day_menu.json` |
| `week_menu.py` | «План на 3 дня»: корзина на период, остатки, генерация дня по факту, прогресс «готово» |
| `stores/` | ссылки магазинов, настройки, MCP ВкусВилла, корзина с ценами, подбор упаковок |

## 5. Данные и настройки

### 5.1. Где что хранится

| Хранилище | Путь | Содержимое |
|---|---|---|
| SQLite аккаунтов | `accounts.db` (переопределяется `ACCOUNTS_DB`) | аккаунты, подписки, платежи, избранное, «полка», FSM, настройки, обратная связь |
| SQLite учёта | `usage.db` (переопределяется `USAGE_DB`) | генерации, лимиты, события, статистика |
| SQLite сайта | `web_data/web.db` (каталог — `WEB_DATA_DIR`) | `devices`, `events`, `ads`, `ad_events`, `kv`, загрузки |
| JSON бота | `user_data.json` | последний запрос, порция, история напоминаний |
| JSON меню | `day_menu.json`, `week_menu.json` | сохранённые меню и планы |
| JSON настроек | `store_prefs.json` | выбранные магазины |
| Память процесса | `last_recipe.py` | последний показанный рецепт (для кнопки «В избранное») |

Идентификация на сайте — без регистрации: `POST /api/device` создаёт случайный код устройства, который
браузер хранит у себя. В общем ядре устройство приводится к `chat_id = 10**12 + id`, поэтому один код
работает и для сайта, и для привязанного Telegram-аккаунта.

### 5.2. Настройки

- Все секреты и параметры читаются **только** через `config.py` из `.env` (`load_dotenv()`).
- Шаблон переменных — `.env.example`; реальный `.env` в git не попадает (см. `.gitignore`).
- Ключевые группы настроек: `BOT_TOKEN`, провайдеры LLM и их ключи, `TAVILY_API_KEY`, лимиты и тарифы
  (`LIMITS_*`, `DAILY_GEN_CAP*`, `PREMIUM_FEATURES`), магазины (`STORE_URL_*`, `VKUSVILL_*`), веб
  (`WEB_SECRET`, `WEB_APP_URL`, `WEB_DATA_DIR`, `WEB_DAILY_LIMIT`), напоминания (`REMINDER_*`),
  платежи (`PAYANYWAY_*`, `PAYMENT_*`), соцсети (`VK_*`, `SOCIAL_*`), админы (`ADMIN_TG_IDS`).

> ⚠️ `.env` содержит секреты: его нельзя читать, логировать или передавать во внешние сервисы.
