## 1. Что это и для кого
Помощник решает вопрос «что приготовить?»: человек отвечает на несколько вопросов — получает один конкретный
рецепт с точными количествами, калорийностью, КБЖУ на порцию и пошаговой инструкцией под его технику (аэрогриль,
мультиварка, духовка, плита), плюс список продуктов, которые можно сразу найти в магазинах. Начинался как бот
«для мамы», теперь есть и сайт, который открывается без Telegram и устанавливается на телефон как приложение.

Владелец проекта ведёт **учёт расходов по каждому проекту отдельно** — у проекта свой ключ DeepSeek; ключи из других
проектов сюда не подставлять.

## 2. Возможности
**Общие (бот и сайт):**
- **Рецепт**: анкета → поиск в интернете → ИИ собирает один рецепт. Типы питания: аюрведическая, классическая,
  сбалансированное питание, питание для набора массы, питание для атлетов циклических дисциплин, «подбор по КБЖУ»
  (цель вроде «500 ккал, белки 40 г» — главный приоритет при подборе).
- **Меню на день**: выбор приёмов пищи (завтрак, бранч, обед, перекус, ужин); все блюда дня генерируются **одним** запросом,
  чтобы продукты переиспользовались (короче список покупок), блюда при этом разные. Дневная цель по КБЖУ делится по долям
  (завтрак 25%, бранч 30%, обед 35%, перекус 10%, ужин 30% — нормируется под выбранный набор).
- **План питания на 3 дня** (пилот, `WEEK_MENU_DAYS=3`): сначала продуктовая корзина на весь период + советы по хранению и
  разморозке; рецепты каждого дня генерируются **по факту** из реального остатка продуктов (остаток и «лимит на сегодня»
  считает код), без повторов блюд; отметка «готово» двигает прогресс.
- **Избранное** (сохранить рецепт, поиск по избранному в боте).
- **Списки покупок** со ссылками на поиск в магазинах; магазины включаются/выключаются (`/stores`); для ВкусВилла — реальные
  цены и ссылка-корзина (официальный экспериментальный MCP, подбор упаковок «минимально достаточно, дешевле всего»).
- Калорийность и КБЖУ — **только на одну порцию** (блок «на всё блюдо» убран намеренно).

**Только бот:** ежедневное напоминание в 14:00 (МСК) с новым блюдом по сохранённым параметрам; нижнее меню из трёх кнопок
(«📋 Показать меню», «🗂 Готовые меню», «❓ Справка»); команды `/menu /ready /stores /app /help`.

**Только сайт:** без регистрации (код устройства); PDF (рецепт / меню / план / всё избранное); установка на главный экран (PWA)
и офлайн-режим; админка `/admin` (статистика, рекламные баннеры); дневной лимит подборов на устройство.

## 3. Как это работает (поток данных)
```
 Telegram (aiogram, bot.py)  ─┐                                   ┌→ ПРОДУКТЫ_СПИСОК → ссылки на магазины (stores/)
                              ├→ анкета (FSM / веб-форма)         │
 Сайт (web/index.html → API) ─┘        │                          ├→ БАЗОВЫЕ_ПРОДУКТЫ / ИСПОЛЬЗОВАНО_БАЗОВЫЕ → остатки плана
                                       ▼                          │
                         search.py: Tavily (резерв DuckDuckGo) → сниппеты рецептов
                                       ▼
                         prompts.py: системный + пользовательский промпт (тип питания, цель КБЖУ, исключения, …)
                                       ▼
                         ai.py: DeepSeek deepseek-flash (thinking: disabled) → при сбое/пустом ответе Groq → OpenRouter
                                       ▼
                         разбор ответа (shopping.py, day_menu.py, week_menu.py) → хранилища (JSON / SQLite) → ответ пользователю
```
Ключевая идея: **ИИ пишет текст рецепта и служебные строки, а код их вырезает и парсит.** Арифметику (остатки, лимиты на день,
подбор упаковок, дедупликация продуктов) делает код, а не модель — модель плохо считает точные граммы на много блюд вперёд.

### 3.1. Служебные строки в ответах ИИ (контракт между промптами и кодом)
| Строка / маркер | Где появляется | Что делает код |
|---|---|---|
| `ПРОДУКТЫ_СПИСОК: продукт1, продукт2, …` | последняя строка каждого рецепта | вырезается из текста; названия → ссылки на поиск в магазинах (`shopping.extract_shopping_terms`) |
| `===СЛЕДУЮЩЕЕ_БЛЮДО===` | между блюдами в ответе «меню на день» / «день плана» | ответ режется на блоки по приёмам пищи (`day_menu.parse_meal_blocks`); число блоков должно совпасть, иначе откат на независимую генерацию |
| `БАЗОВЫЕ_ПРОДУКТЫ: продукт=число, …` | корзина плана | вырезается; число (граммы, мл, для яиц штуки) → начальный остаток (`shopping.extract_base_products`) |
| `ИСПОЛЬЗОВАНО_БАЗОВЫЕ: продукт=число, …` | последний блок ответа «день плана» | вычитается из остатка (`week_menu._generate_day`) |
| `🍽 Название` | первая строка рецепта | название блюда для кнопок и избранного (`shopping.extract_dish_title`) |

### 3.2. Надёжность
- **Фолбэк провайдеров** (`ai.call_llm_with_fallback`): пустой ответ или ошибка → следующий провайдер. В сентябре Groq с моделью
  `openai/gpt-oss-120b` отвечал «200 OK» с пустым текстом (предположительно из-за скрытых рассуждений) — это и привело к
  смене основного провайдера на DeepSeek.
- **DeepSeek**: старые имена `deepseek-chat`/`deepseek-reasoner` отключены 24.07.2026; используется `deepseek-flash`,
  режим размышлений у него включён по умолчанию, поэтому в каждый запрос явно кладётся `thinking: {"type": "disabled"}`.
- **Меню на день**: совместная генерация; при несовпадении формата — откат на независимую генерацию каждого блюда.
- **Поиск**: Tavily; при ошибке/пустом ответе — DuckDuckGo (на сервере он часто режет «202 Ratelimit»); если пусто — ИИ работает по своим знаниям.
- Пустой текст рецепта и любые исключения в боте перехватываются — пользователь видит понятное сообщение, а не тишину.

## 5. Telegram-бот
**Нижнее меню (всегда на месте):** «📋 Показать меню» · «🗂 Готовые меню» · «❓ Справка».
**Главное меню** (inline): типы питания по 2 в ряд → «🎯 Подобрать по КБЖУ» → «📅 Меню на день», «📆 Меню на 3 дня» →
«⭐ Избранное», «🏪 Магазины», «❓ Справка».
**Анкета «рецепт»:** тип питания → (цель КБЖУ, если выбран «по КБЖУ») → что использовать или какое блюдо → что исключить →
время (15/30/45/60/не важно) → порции (1–6) → техника (мультивыбор) → подтверждение → поиск и генерация → рецепт ОДНИМ сообщением с кнопками «🛒 Найти продукты в магазине» (→ выбор магазина →
короткий список ссылок только на него, магазин можно переключать на месте), «⭐ В избранное», «🍳 Подобрать ещё рецепт».
Список ссылок не вываливается сразу: то же для меню на день (кнопка в сводке), корзины плана и «докупить к дню N».
**«Меню на день» / «План на 3 дня»:** те же шаги плюс выбор приёмов пищи; результат — свёрнутый список, который
раскрывается в рецепт и сворачивается **редактированием того же сообщения** (чат не засоряется).
**План питания:** после создания приходят корзина, ссылки на магазины и (если доступны) цены ВкусВилла; «🍳 Готовить день N» →
рецепты дня; «✅ Готово» двигает прогресс; ◀/▶ навигация.
**Пространства callback_data:** `cuisine:`, `skip:`, `time:`, `servings:`, `appliance:`, `confirm:go|restart`, `daymeal:`,
`daymenu:start|show|collapse`, `weekmenu:start|open|basket|cook_next|slot|done|status`, `ready:day|week`, `favorites:`/`fav:`,
`stores:`, `menu:open`, `help:open`. Нажатия старых кнопок нижнего меню (прошлые версии) обрабатываются и обновляют клавиатуру.
**Напоминания:** `reminders.py`, в 14:00 `Europe/Moscow` всем из `user_data.json` (кто хоть раз получал рецепт) — кнопки
«Приготовить» / «Найти другой рецепт».

## 6. Сайт (веб-версия)
**Вкладки:** «Создать» (форма: режим «Рецепт / Меню на день / План на 3 дня», тип питания, продукты, исключения, время, порции, техника),
«Готовые меню» (меню на день и план по дням со статусами ✅/«новый»/🔒, корзина, хранение и разморозка), «Избранное».
**Где купить:** в блоках со списком продуктов («Найти продукты в магазине», «Корзина на весь план») сначала надо выбрать магазин (Пятёрочка / ВкусВилл / Перекрёсток / Лавка / Купер; ничего не выбрано заранее и выбор не запоминается) — только после этого показываются ссылки на поиск в нём. При выборе ВкусВилла сразу собирается корзина с ценами (`POST /api/cart` → `stores/basket.py`, официальный MCP, до ~40 с); в боте то же делает кнопка «🧺 Собрать корзину».
**Без регистрации:** при первом визите `POST /api/device` создаёт случайный код (32 hex-символа), браузер хранит его в
`localStorage["dev"]` и шлёт в заголовке `X-Device`. На сервере под этим кодом лежат избранное и меню. Очистка данных браузера =
потеря доступа к ним (поэтому — PDF). Для общего ядра используется `chat_id = 10**12 + id устройства`, чтобы не пересекаться с Telegram.
**Долгие операции:** `POST /api/recipe|daymenu|week|week/cook` создаёт фоновую задачу (asyncio) и возвращает `job`; страница опрашивает
`GET /api/job/{id}` каждые 2 с (до ~5 минут). Задачи живут в памяти процесса (при перезапуске теряются).
**Ограничения (только веб, бот без лимитов):** 3 блюда в сутки (`WEB_LIMIT_RECIPE`), 1 меню на день в сутки (`WEB_LIMIT_DAYMENU`), 1 план на 3 дня за 3 календарных дня по Москве (`WEB_LIMIT_WEEK`); при сбое ИИ попытка возвращается; при превышении — сообщение «На сегодня лимитов больше нет»; одна задача на устройство одновременно, не более 20 новых
устройств в час с одного IP, 5 неверных паролей админки за 10 минут, 200 PDF в сутки на устройство.

| Эндпоинт | Что делает |
|---|---|
| `GET /`, `GET /admin` | страницы |
| `GET /manifest.webmanifest`, `GET /sw.js`, `/icons/*` | PWA |
| `POST /api/device`, `POST /api/visit`, `GET /api/meta` | устройство, статистика визита, справочники формы |
| `POST /api/recipe`, `/api/daymenu`, `/api/week`, `/api/week/cook` | запуск генерации (ответ — `job`) |
| `GET /api/job/{id}` | статус задачи |
| `GET /api/overview`, `/api/day`, `/api/week` | чтение меню; `POST /api/week/done/{i}` — отметка «приготовил» |
| `GET/POST /api/favorites`, `DELETE /api/favorites/{id}` | избранное (до 200) |
| `POST /api/pdf` | PDF: `{items:[{title,text}], name}` → файл (рецепт, меню, план, избранное) |
| `GET /api/ad?slot=top\|inline`, `GET /go/{id}` | показ баннера и счётчик кликов с редиректом |
| `POST /admin/login`, `/admin/api/stats`, `/admin/api/ads…` | админка: вход (cookie `adm` = HMAC), статистика, управление баннерами |
| `GET /api/health` | проверка живости |

**PDF** (`web_pdf.py`): шрифт DejaVu Sans на сервере (`/usr/share/fonts/truetype/dejavu`); эмодзи отбрасываются, «двойники» вроде
неразрывного дефиса заменяются обычным («5‑6 мин» не превращается в «56 мин»); при ошибке сайт открывает диалог печати.
**PWA:** манифест + service worker (кэш только оболочки; `/api`, `/admin`, `/go`, `/uploads` не кэшируются; страница берётся из
сети, из кэша — только офлайн; при изменении кэшируемых файлов поменяй `CACHE` в `sw.js`). Карточка «На главный экран»:
Android/Chrome — системное окно, iPhone — инструкция «Поделиться → На экран Домой» (только Safari), внутри iframe Тильды и в
встроенных браузерах — предложение открыть отдельно.
**Реклама:** места `top` (вверху «Создать») и `inline` (после рецепта/меню); баннеры загружаются в админке (картинка ≤1,5 МБ).
Рекламные сети (Яндекс РСЯ) не подключены.

## 12. Журнал ключевых решений (чтобы не «изобретать заново»)
- **Типы питания** вынесены в `cuisines.py`; «подбор по КБЖУ» — отдельная ветка анкеты, цель идёт в промпт как главный приоритет, сравнивать нужно только те показатели, что названы.
- **КБЖУ только на порцию**: блок «на всё блюдо» убран — дублировал данные и занимал место.
- **Модель ИИ**: перешли с Groq (пустые ответы у gpt-oss) на DeepSeek; затем со старого `deepseek-chat` на `deepseek-flash` + `thinking: disabled`; фолбэк-цепочка провайдеров.
- **Поиск**: Tavily основной (DuckDuckGo с сервера упирается в рейтлимит) — DuckDuckGo оставлен как резерв.
- **Меню на день**: один совместный запрос вместо N независимых — ради переиспользования продуктов; одинаковые продукты в разных блюдах называются одинаково.
- **План питания**: не генерировать всё заранее (хрупко и устаревает при отклонении от плана); сначала корзина, остаток — данные в JSON, рецепты дня — по факту.
  В тесте ИИ съедал курицу за 2 дня из 3 — поэтому «лимит на сегодня = остаток ÷ дней осталось» считает код и передаёт в промпт.
- **Напоминание** не закрепляет название прошлого блюда (иначе каждый день «спагетти»), кнопки «Приготовить» / «Найти другой рецепт».
- **Интерфейс**: рецепты в меню раскрываются/сворачиваются правкой того же сообщения; постоянное нижнее меню из трёх кнопок.
- **Веб**: автономный сайт на своём поддомене вместо страницы на Тильде + ссылок из Telegram (всегда доступен, без привязки к боту); без регистрации (код устройства); PDF — настоящий файл; PWA.
- **Деплой**: SSH-доступ и `update_cooking.bat`; `.env` не в git; на сервере порты чужих проектов не занимать (веб — 8101).
- **Работа несколькими сессиями ассистента в одной папке** — возможна (так появились магазины, новое меню и сайт). Перед деплоем сверяй `git status`, чтобы знать, что именно уйдёт.
