# Правила работы над проектом

## 0. Контекст
Перед началом любой задачи ОБЯЗАТЕЛЬНО прочитай файл `docs/ARCHITECTURE.md`, чтобы понять устройство проекта.

## 1. Безопасность (Бэкапы)
Перед тем как начать любую задачу по изменению кода, ты ОБЯЗАН создать новую Git-ветку (например, `git checkout -b fix/имя-задачи` или `feature/имя-задачи`). Никогда не работай напрямую в ветке main/master.

## 2. Тесты до кода
Если это исправление бага — сначала напиши тест, который воспроизводит этот баг (он должен упасть). Если это новая фича — сначала опиши, как мы будем ее тестировать.
Не вноси изменения в логику, если для них нет тестов или проверок. Не пиши "готово", пока не убедишься, что старые тесты проходят.

## 3. Процесс работы
Сначала предложи план, потом пиши код. Если правишь больше 3 файлов — жди подтверждения пользователя.
Одна задача = одна ветка = один логичный коммит.
Не трогай `.venv`, `.env`, миграции. Зависимости не ставь без спроса.
